# 运行说明

## 1. 部署形态

本地单机或内网单机部署：一个 Uvicorn 进程监听 `127.0.0.1:8000`，同时提供静态页面与 REST 接口，不依赖数据库、消息队列或外部服务。所有状态（模型、阈值、历史、视频结果）都落在项目目录内的文件里，进程重启后模型与阈值仍在，内存中的会话历史会清空。

前端为原生 HTML/CSS/JS，无需 Node.js、无需构建，直接由后端静态托管。

## 2. 运行环境

| 项 | 要求 |
| --- | --- |
| 操作系统 | Windows / Linux / macOS |
| Python | 3.9 及以上 |
| 深度学习 | torch 1.12+、torchvision 0.13+ |
| GPU | 可选。有 NVIDIA GPU 时推理快 5–10 倍，8 GB 显存足够 |
| 其它依赖 | 见 `requirements.txt` |

`torch` / `torchvision` 需按本机 CUDA 版本单独安装，不能直接 `pip install torch`（会装成 CPU 版）：

```bash
# 有 GPU：按 https://pytorch.org/get-started/locally/ 选对应 CUDA 版本的命令
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121

# 其余依赖
pip install -r requirements.txt
```

资源参考：单张 1024×1024 输入缩放到 512，峰值显存约 0.6 GB；GPU 下单张推理约 30–60 ms，纯 CPU 约 1 s。无 GPU 时 `torch.cuda.is_available()` 为假会自动退回 CPU，功能不受影响，只是慢。

## 3. 启动

```bat
cd /d <项目目录>
start_web.bat
```

脚本会先 `chcp 65001` 切到 UTF-8 再启动，避免中文输出在 GBK 控制台乱码；并把 Python 路径写在 `PY` 变量里，路径不对时打印明确错误而不是静默失败。

手动启动等价命令：

```bat
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

| 判定条件 | 执行步骤 | 预期结果 |
| --- | --- | --- |
| 服务可启动 | 双击 `start_web.bat` | 控制台出现 `启动服务: http://127.0.0.1:8000` 与 `Uvicorn running on http://127.0.0.1:8000` |
| 健康检查 | `curl http://127.0.0.1:8000/health` | 返回 `{"status":"ok","tasks":["example"],"version":"1.0.0"}` |
| 端口被占用 | 已有进程占用 8000 时再次启动 | uvicorn 报 `[Errno 10048]` 并退出；改用 `--port 8001` 重新启动 |
| 解释器缺失 | 改坏 `start_web.bat` 里的 `PY` 后运行 | 输出 `[错误] 未找到 Python 解释器` 并 `exit /b 1`，不会挂起 |

## 4. 目录与产物

| 路径 | 内容 | 生成时机 |
| --- | --- | --- |
| `models/<task>/memory_bank.npz` | 特征库 + 随机投影矩阵 + 建模元信息（fp16 存库） | `det.train` 或界面「后台重新建模」 |
| `models/<task>/threshold.json` | 图像级/像素级阈值与标定来源 | 建模时写入；界面「应用阈值」时更新 |
| `runs/<task>/eval_<task>.json` `.md` | 评估指标与逐类检出表 | `det.eval` |
| `runs/<task>/videos/<job_id>/` | 视频处理结果帧（`f000001.jpg` 命名） | 上传视频后 |
| `runs/<task>/anomalies/` | 判定异常时存档的原图 + 热力图 + 掩码 | 勾选「异常图存档」后 |
| `runs/server.out.log` `.err.log` | 服务端输出 | 后台启动方式下 |

## 5. 接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 健康检查、任务列表、版本 |
| GET | `/api/tasks` | 任务元信息：显示名、缺陷类别、模型是否就绪、当前运行时阈值、任务状态 |
| GET | `/api/tasks/{task}/state` | 该任务运行态（阈值、最近输入、最近结果、历史、推理计数） |
| POST | `/api/tasks/{task}/clear` | 清空该任务的最近输入、最近结果与历史 |
| GET | `/api/tasks/{task}/history?limit=` | 历史记录 |
| POST | `/api/tasks/{task}/threshold` | 更新图像级/像素级阈值并持久化到该任务自己的 `threshold.json` 与 `configs/<task>.json` |
| GET | `/api/tasks/{task}/model` | 模型信息（路径、库条目数、输入尺寸、建模样本数、构建时间） |
| POST | `/api/tasks/{task}/model/load` | 加载/强制重载模型 |
| POST | `/api/tasks/{task}/model/build` | 后台线程重建特征库（返回后状态为 `building`，进度由 `/api/tasks` 展示） |
| POST | `/api/infer/{task}` | 上传图片推理（multipart：`file`、`save_anomaly`），上限 20 MB |
| POST | `/api/infer/{task}/frame` | 摄像头实时帧推理（JSON：`image` 为 dataURL、`record`、`overlay_quality`），上限 12 MB |
| POST | `/api/infer/{task}/batch` | 多图批量推理（multipart，多文件字段 `files`）；结果只返回不写入历史，供脚本调用，界面未接入 |
| POST | `/api/tasks/{task}/video` | 上传视频做逐帧检测（`file`、`target_fps`），上限 800 MB |
| GET | `/api/video/{job_id}` | 单条视频任务状态与逐帧结果 |
| GET | `/api/videos?task=` | 该任务视频任务列表 |
| POST | `/api/video/{job_id}/cancel` | 取消视频任务 |
| GET | `/api/tasks/{task}/export?fmt=csv\|json` | 导出该任务历史（CSV 带 BOM，Excel 直接可读） |
| GET | `/media/*` | 访问 `runs/` 下的产物（视频结果帧、异常存档） |
| GET | `/` | 单页界面 |

任务参数 `{task}` 只接受 `configs/` 下已存在的任务名，其它值返回 404，不会回落到默认任务。

## 6. 排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面空白、控制台 `Failed to fetch` | 后端未启动或端口不同 | 确认 `start_web.bat` 在跑，访问的端口与启动参数一致 |
| 上传图片提示「该任务尚未建模」 | `models/<task>/memory_bank.npz` 不存在 | 先 `python -m det.train --task <task>`，或在界面点「后台重新建模」 |
| 摄像头无画面 | 浏览器未授权或页面不是 `127.0.0.1`/`localhost` | 允许摄像头权限；`getUserMedia` 仅在安全上下文（localhost 或 HTTPS）可用 |
| 控制台中文乱码 | 终端代码页是 GBK | 用 `start_web.bat`（已 `chcp 65001`），或先执行 `chcp 65001` |
| 首次推理明显变慢 | CUDA 上下文初始化与模型懒加载 | 预热一次即可，之后稳定在实测延迟区间 |
