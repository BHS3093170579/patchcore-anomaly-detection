# 模型配置说明

## 1. 方法：PatchCore（免训练）

不使用任何缺陷样本，也不需要反向传播。流程：

1. **特征提取**：ImageNet 预训练的 WideResNet50-2（冻结）对正常图取 `layer2` 与 `layer3` 两段中间特征；`layer3` 双线性插值到 `layer2` 分辨率后按通道拼接，512 输入下得到 64×64×1536。
2. **局部邻域聚合**：3×3 平均池化（`padding=1`），抑制单像素噪声。
3. **构建特征库**：每张正常图贡献 64×64 = 4096 个 patch，全部堆叠后先随机抽样到至多 30000 个候选，再用 k-center 贪心采样压缩到 `coreset_ratio × 总 patch 数`，存成 memory bank（fp16）。
4. **打分**：测试图同样提特征，每个 patch 取到特征库的最近邻 L2 距离 → 得到 64×64 异常图 → 高斯平滑（`smoothing_sigma`）→ 取最大的 `score_topk` 个像素的均值作为**图像级异常分**；异常图本身用于**像素级定位**。

距离越大越异常，因此是「单类、正向异常分」的设定，不需要为缺陷类别训练分类器。

## 2. 参数表（`configs/<task>.json` → `model` 段）

| 参数 | 建议值 | 含义 | 调整影响 |
| --- | --- | --- | --- |
| `backbone` | `wide_resnet50_2` | 特征提取网络 | 换 `resnet18` 更快但精度下降；换 DINOv2 对结构类有益但需额外权重 |
| `weights` | `IMAGENET1K_V2` | torchvision 预训练权重 | 无需改；首次运行下载约 263 MB 到 `~/.cache/torch` |
| `layers` | `["layer2", "layer3"]` | 取哪几段中间特征 | 只用 `layer3` 更快、更偏语义；两段并用对小缺陷更敏感 |
| `input_size` | `512`（细缺陷用 640） | 送入网络的方形边长 | 越小越快（显存/延迟近似平方关系）；缺陷像素占比 < 2% 时建议提到 640，代价是延迟约 1.5 倍 |
| `coreset_ratio` | `0.004` | 特征库保留比例（相对总 patch 数） | 调大召回更高、内存与检索耗时上升；经验上 0.004 已接近饱和，提到 0.02 精度提升通常不足 0.5 个点 |
| `projection_dim` | `128` | 随机投影目标维度（1536 → 128） | 越大越准、检索越慢；128 是速度与精度的折中 |
| `neighbors` | `1` | 最近邻个数 | 当前实现取最小值（1-NN）；大于 1 未启用，保留字段 |
| `smoothing_sigma` | 纹理 1.0 / 结构 4.0 | 异常图高斯平滑 sigma | 过大使小缺陷扩散、定位变粗；过小则噪点增多 |
| `score_topk` | 30–100 | 图像分取异常图前 k 个像素均值 | 过大对孤立噪点不敏感、整体分偏低；过小易受单点噪声影响 |
| `seed` | `0` | 投影矩阵与 coreset 随机性 | 固定后重建模结果可复现 |

投影矩阵在 `memory_bank.npz` 里按 `seed` 生成并保存，因此**换 seed 必须重建模**。

## 3. 任务隔离与新增任务

代码按任务名组织，每个任务各自独立读写，互不影响：

| 项 | 位置 |
| --- | --- |
| 配置文件 | `configs/<task>.json` |
| 模型目录 | `models/<task>/` |
| 输出目录 | `runs/<task>/` |

**接入新任务**：复制 `configs/example.json` 为新文件名（文件名即任务名），改 `dataset_root`、`display_name`、`accent`、`model_dir`、`runs_dir`，然后执行 `python -m det.train --task <新任务名>`。`available_tasks()` 会自动扫描 `configs/*.json`，界面上随即出现新任务。

代码层面通过 `det/config.py::load_task_config(task)` 按任务名读取配置，`Detector(task)` 只加载自己那一份特征库与阈值；Web 层的 `RuntimeManager` 也按任务分别持有运行态，切换任务不会串数据。

**为什么必须按任务隔离**：不同产品的正常样本分布不同，混成一个特征库会互相稀释异常分（正常样本被判异常）；不同品类的分数尺度也不同，共用阈值会让其中一类大量误报。

## 4. 阈值机制

| 字段 | 含义 |
| --- | --- |
| `threshold.image_score` | 图像级判定阈值：`异常分 > 阈值` 即判异常 |
| `threshold.pixel_score` | 像素级定位阈值：异常图中 `≥ 阈值` 的连通域被提取为缺陷区域 |
| `threshold.calibrated_from` | 标定来源，`train_good_holdout(n=N)` 表示用留出的正常图标定；`manual` 表示界面上手动改过 |
| `threshold.normal_quantile` | 标定时取正常样本分数的分位数（默认 0.995） |
| `threshold.safety_margin` | 分位阈值再乘的安全系数 |

标定流程：建模时把正常图按 9:1 切分，90% 建库、10% 留出；对留出集计算异常分，取 `normal_quantile` 分位、再乘 `safety_margin` 作为图像级阈值，像素级阈值同理。

**为什么需要 `safety_margin`**：留出集通常只有二三十张，0.995 分位已经贴着最大值，统计上不稳定；而线上正常样本可能与训练集有轻微分布差异。这个系数直接对应「误报 vs 漏检」的取舍——**系数越小越偏向召回**：

```
系数 ↓  →  阈值 ↓  →  召回 ↑  误报 ↑
系数 ↑  →  阈值 ↑  →  召回 ↓  误报 ↓
```

产线部署时应按漏检与误报的实际代价重新标定：

```bash
python tools/recalibrate.py --task <task> --margin <值>
```

打分前还有一步**边缘衰减**（`det/engine.py::score_map`）：patch 网格外圈对应原图外框，卷积特征在边界处感受野被截断，会稳定产生高分伪影。因此按每个 patch 到图像边界的距离乘权重 `clip(d/2.5, 0.25, 1.0)`，并把距边界 ≤3 个 patch 的连通域从区域列表剔除。改动后阈值需要重新标定。

阈值可在界面「判定阈值」卡片直接改，点「应用阈值」后同时写入 `models/<task>/threshold.json` 与 `configs/<task>.json`，且不会重算已有历史记录（历史保留当时的判定结果）。

## 5. 模型保存格式

`models/<task>/memory_bank.npz` 是一个 NumPy 压缩包，含三个数组：

| 键 | 形状 / 类型 | 说明 |
| --- | --- | --- |
| `bank` | `(N, 128)` float16 | 压缩后的正常 patch 特征库 |
| `projection` | `(1536, 128)` float32 | 随机投影矩阵，推理时必须与建模时一致 |
| `meta` | 0 维字符串数组 | JSON 文本：backbone、layers、input_size、projection_dim、coreset_ratio、bank_size、feature_dim、n_train_images、n_calib_images、built_at、device、torch 版本 |

`models/<task>/threshold.json` 是纯 JSON，字段见上表。两者都由 `MemoryBank.save()` / `Detector.set_threshold()` 写入，路径取自配置里的 `model_dir`。

## 6. 重建模

```bash
python -m det.train --task <task>
```

或在界面点「后台重新建模」：后端起线程执行，`/api/tasks` 的 `state.state` 变为 `building`，完成后写回 `models/<task>/`，页面通过轮询看到状态变化。重建期间旧的模型文件不会被半写坏（先写临时文件再替换）。

耗时参考：200 张 512×512 的正常图，消费级 GPU 约 65 秒，纯 CPU 约 6 分钟。

## 7. 已知限制

- **需空间上下文才能区分的缺陷偏弱**：例如「零件装反/位置互换」这类仅靠局部纹路无法判断的异常，patch 级特征不容易捕捉，需要提高输入分辨率或辅以结构化规则。
- **小面积缺陷对分辨率敏感**：缺陷像素占比低于 2% 时，输入从 512 降到 384 会导致漏检明显增加。
- 仅做「正常 / 异常」二分类与异常定位，**不输出缺陷类型**；界面里的「高分/中分/低分」是按 `peak / 像素阈值` 的比值分档，不是分类结果。
- 建模样本分布必须接近实际产线；若光照、镜头、工位变化大，需要重新采正常样本建模。
